# task-011 — 터미널 복사 개선 + 화면 깨짐 원인 제거

## 상태
- 생성일: 2026-09-26
- 요청: "터미널의 텍스트를 복사하지 못하는 부분이 있다, Ctrl+C로 복사할 수 있게"
- 우선순위: P0

## 원인
1. Claude/Codex/Grok TUI는 화면을 계속 다시 그려서, 드래그한 선택이 `Ctrl+C`를 누르기 전에 풀릴 수 있다.
2. 선택이 불가능한 긴 출력(스크롤백)을 통째로 가져올 방법이 없었다.
3. **(조사 중 발견, task-010 증상의 주원인)** main이 AOR 폴백 경고를 PTY를 거치지 않고 xterm에 직접 써 넣었다 →
   ConPTY/PowerShell이 아는 커서 위치와 실제 화면이 어긋나 이후 출력이 엉뚱한 줄에 덮어써지고 프롬프트가 깨져 보였다.
   이 PC는 AOR 엔진이 없어 **모든 페인**이 이 경고를 받았다.

## 구현
- copy-on-select: 드래그를 놓는 순간(mouseup) + 키보드/더블클릭 선택 변경 시 클립보드에 복사
- `Ctrl+C`(선택 있을 때 복사 후 선택 해제 → 다음 `Ctrl+C`는 중단 신호), `Ctrl+Shift+C` 유지
- 우클릭 메뉴: *보이는 화면 복사*, *전체 출력 복사* (wrapped 줄 병합, UTF-8 1MB 상한 — 오래된 앞부분부터 자름)
- 앱이 마우스 모드를 켜면 페인 헤더에 *Shift+드래그로 선택* 안내 (xterm의 강제 선택)
- 경고는 `pty:spawn` 결과로 돌려주고 페인 헤더(⚠ + 툴팁)와 FLOW 상태줄에 표시 — 터미널에 직접 쓰지 않음

## 검증 (`npm run test:smoke` 36/36)
- 실제 마우스 드래그 → 클립보드에 복사됨 (Ctrl+C 없이)
- 선택 후 `Ctrl+C` → 복사됨
- 폴백 경고가 터미널 텍스트에 없고 헤더에 표시됨

## 한계
- Shift+드래그 안내는 자동 테스트 미검증: 이 PC의 ConPTY는 VT 앱의 마우스 모드 요청(`ESC[?1000h`)을 xterm에 전달하지 않아
  재현이 안 됨. 콘솔 API로 마우스 입력을 켜는 TUI(crossterm 기반 등)에서만 표시된다.
- *보이는/전체 출력 복사*는 네이티브 메뉴라 CDP로 클릭할 수 없어 코드 리뷰로 검증.

## 리뷰 반영 (logs/review/task-010-011_input-copy.md)
- 오래된 선택이 중단용 Ctrl+C를 막던 문제: 사용자가 타이핑하면 선택 해제 — "타이핑 후 Ctrl+C는 복사 안 함" 스모크
- 자동 복사는 이번 드래그로 선택이 바뀐 경우에만 (클릭만으로 클립보드 덮어쓰기 안 함)
- 전체 출력 복사: 줄 단위 바이트 예산으로 최신 줄부터 담기 (문자 중간 절단·반복 인코딩 제거)
- `term-menu:show`: 살아 있는 세션 id만 허용
