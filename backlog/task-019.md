# task-019 — 콘솔 에러를 버튼으로 채팅 입력창에

## 요청
"새 콘솔 에러를 채팅에 첨부" 부분이 체크박스라 버튼이 없음 → 클릭하면 채팅창(입력창)에 들어가게.

## 변경
- 체크박스(`#br-include-errors`, 보낼 때 자동 첨부) → 버튼 `#br-errors-to-chat` "⚠ 새 콘솔 에러 N건 → 채팅에 넣기" (새 에러 없으면 비활성)
- 클릭: 마지막 전송 이후의 새 에러(최대 8건 + 생략 건수)를 입력창에 이어 붙임 — 보내기 전에 보고 고칠 수 있음. 두 번 눌러도 한 번만
- 자동 첨부는 없앰(같은 에러 중복 방지). 에러는 버튼으로 넣은 블록으로만 전달
- 보호 유지(review C3): 넣은 줄은 모두 `# ` 주석이고 main에서 제어문자·줄바꿈이 이미 제거됨. 그 블록이 입력 내용에 남아 있으면 주석과 같은 경로(에이전트 페인 전용, guarded paste)로만 전송, 일반 셸이면 거부하고 입력 내용 유지
- "보냄" 처리는 실제 전달된 뒤에만, 넣은 시점까지의 에러만 (그 뒤 에러는 계속 새 에러)

## 테스트
- test:browser 72 (버튼 개수 표시, 클릭 시 입력창 삽입·`# ` 주석, 중복 삽입 없음, 보내기 전엔 새 에러 유지, 일반 셸 거부 시 입력 유지, 에이전트 전달 후 비활성, 악성 페이지 문자열 정리 확인)
- unit 229, smoke 50, resume 27

## r1 리뷰 반영 (Critical 4 / Major 2 / Minor 2)
- **페이지 유래 판정 = 넣은 에러의 메시지 본문**(머리줄 문자열 아님). 본문이 남아 있으면 `# `·머리줄을 지워도, 기록(↑)으로 불러와도 페이지 유래 (최근 50개 삽입분 기억)
- 브라우저가 닫혀 있으면 페이지 유래 텍스트 전송 거부(입력 유지)
- 넣은 문서와 현재 문서가 다르면(이동·새로고침) 전송 거부
- 일반 터미널 붙여넣기 차단: 우클릭 붙여넣기·Ctrl+Shift+V(클립보드)·Ctrl+V(paste 이벤트, capture 단계). 에이전트 페인은 허용
- 빠른 두 번 클릭: 삽입 중 잠금 + 버튼 비활성
- 사용자가 쓴 끝 공백·빈 줄 보존, 구분 줄바꿈만 필요할 때 추가
- 에러 "보냄"은 삽입분마다 한 번만 (기록에서 다시 보내도 중복 처리 없음)

## 테스트

- unit 229

## r2 리뷰 반영 (Critical 3 / Major 1)
- 전송 실패·예외 fail-closed: 입력 내용이 페이지 유래면 `decorate` 예외나 보호 경로가 아닌 결과는 모두 거부(입력 유지)
- 터미널 직접 붙여넣기는 에이전트 페인에도 금지 — main의 guarded 검사를 건너뛰므로 입력창 전송만 허용
- 입력창의 **모든** 삽입 블록 검사: 하나라도 다른 문서 것이면 전체 거부. 보낼 때는 함께 간 블록 모두 "보냄" 처리(main 커서는 가장 늦은 표시까지, 단조 증가)

## 테스트
- test:browser 87 (+5: decorate 예외 fail-closed, 에이전트 페인 직접 붙여넣기 차단(Ctrl+Shift+V·paste 이벤트), 두 문서 블록 공존 시 거부, 실제 ↑ 기록 불러오기 거부)
